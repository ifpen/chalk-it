2. HANDLING “BIG DATA” ON THE FRONT END
────────────────────────────────────────────────────────────────────────────
Because the dataset can be large (far more than the 20-row sample), consider these techniques to avoid overloading the browser:

• Incremental Loading (Pagination): Use the dataset’s API attributes (e.g., “offset” and “limit” parameters from the OpenDataSoft endpoint) to retrieve data in chunks.  
• Lazy Loading / On-Demand Fetch: Initially load a limited time range or set of records. Provide UI controls (date pickers, filters) that, when changed, trigger new requests.  
• Aggregation / Preprocessing: Instead of fetching every hourly record for a year at once—hundreds of thousands of rows—fetch aggregated data (e.g., daily totals if the API or a transformation allows) or use smaller intervals.  
• Client-Side Caching: Store fetched data in a local data structure or in the browser’s localStorage/sessionStorage if performing offline or repeated interactions. This reduces API calls.
